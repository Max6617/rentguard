ONE BOUNDARY, READ FROM THE CODE RATHER THAN MEASURED (conservative direction)
  `heartbeat_files` skips a candidate on **any** `OSError`, so a heartbeat whose `stat` is refused
  for a reason other than "gone" (a permission or ACL refusal) is dropped with the pruned ones and
  the tool reads NO GUARD while a guard is writing. That is the safe direction — it under-reports
  protection rather than over-reporting it — and a tool cannot report what it cannot stat; recorded
  so the choice is deliberate rather than accidental.

STILL OPEN — FORGE'S COUNT QUESTION, WITH MY ANSWER
  Measured at this tip: with a crashed guard's file and a live guard's file both present, the line
  names only the live guard, and neither the prose nor `facts` says a guard died (`guards` is not a
  key; the crashed pid does not appear). So a caller cannot tell one guard from three, and a guard
  that died is invisible while another works.
  Recommendation, if the ruling wants it closed: the reported reading answers "is anything watching?"
  and should stay single; the **set** belongs beside it — `guard.guards: N` with
  `guard.others: [{pid, ended, age_minutes, stale}]` for the readings that are not the reported one,
  and a `doctor` warn when any reading is a crashed guard (unmarked, dead pid), because a guard that
  died is evidence and `doctor` is where an operator looks for exactly that. Per-guard `stale` then
  falls out of the same array rather than needing its own field.

LESSON FOR MY OWN LANE (the CI red was worth the cost)
  A test that uses a seam to simulate another platform's behaviour must be paired with a seam-free
  case, or it passes on one host and fails on the other. `test_things_that_are_not_pids_are_gone`
  used the real `os.kill` for 1.5 and was green on Windows, red on every Linux job.
