FINDING 8 (new, money direction) — a status that is neither live nor terminal closes the row.
  `_confirm_stopped`'s own docstring: "EXITED, TERMINATED or gone (None) means it can no longer
  bill, and anything else means it still can." The code is the opposite for every status outside
  `LIVE_STATUSES`: `if last not in LIVE_STATUSES: return True`.
  Measured: a pod reporting **STOPPING** (neither live nor terminal) with a stop call that is
  accepted but leaves it shutting down -> `down` exits 0, `action: "stopped"`, and the row closes,
  so the machine bills with nothing recording it. The listing gate cannot catch it: `_listed_live`
  uses the same `LIVE_STATUSES`, so both witnesses agree that a machine in a transitional state has
  stopped.
  Reachability: any provider status outside the two sets (a transitional or provider-specific
  state). Severity: money direction — the closed row for a possibly-billing machine is the shape
  B19 exists for. The fix is the docstring's rule: only EXITED, TERMINATED or gone may close a row.

FINDING 9 (new, robustness) — `nan` and `inf` crash instead of being refused.
  `--uptime-hours` takes a float, so `nan` and `inf` parse. `estimate <= 0` cannot see either

  raises: ValueError for NaN, OverflowError for infinity. Exit is a traceback, not a named refusal.
  Reachability: a typo, and the same input class the negative-estimate fix just addressed. Not
  severe. A named refusal ("not a length of time") already exists for `<= 0` and fits here.
